LivingThread is an agent that keeps shared details aligned across Slack, Google Docs, and Gmail. It helps people coordinating projects, events, and customer communications avoid a familiar problem: a plan changes in one application, while documents and email drafts continue carrying the old information.

During an explicitly enabled work session, LivingThread automatically connects differently worded references to the same event across configured Slack channels, open Google Docs, and Gmail composers. When it finds a meaningful inconsistency, it shows up inside the affected document or draft with source evidence and proposed next steps. Users do not need to predict which details might become inconsistent, manually link each item, or ask a chatbot to compare them. The environment supplies both the trigger and the context: the team's conversation, the maintained document, and the message currently being written.

Our demo shows a confirmed venue change in Slack while a document and customer email still say “third floor.” LivingThread appears in Google Docs, makes the same connection available in Gmail, and proposes precise updates to both applications. The user reviews the before-and-after wording, approves the changes, and sees verified save results.

LivingThread also understands intentional differences. When the email says 14:00 and the demo starts at 15:00, the user explains that Morgan should arrive one hour early. The agent reconsiders its interpretation and proposes clearer wording that preserves both the early arrival and the official event time. After approval, it updates and verifies the saved draft. Human explanations change the proposed action, extending the interaction beyond dismissing an alert.

The working prototype uses a Manifest V3 Chromium extension, vanilla JavaScript, HTML/CSS, and a Shadow DOM interface, validated in Microsoft Edge. A local Node.js 22+ service uses native HTTP, fetch, and WebSocket APIs for orchestration. Azure-hosted gpt-5.6-sol, accessed through the Responses API, produces structured findings and action proposals. Slack connects through Socket Mode and the Web API; Gmail uses content-script integration with open composers; Google Docs uses authenticated text exports and a restricted debugger bridge for approved editor actions.

Exact-target validation, source-version checks, explicit action approval, save verification, and a durable operation journal help prevent stale edits and blind retries. The project includes 104 passing automated tests and demonstrations in real applications using fictional business details.

LivingThread's innovation is context-driven intervention: recognizing when assistance is needed and bringing understanding, review, and action directly into ongoing work. Different apps. One living thread.
